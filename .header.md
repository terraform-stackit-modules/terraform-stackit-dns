# Terraform STACKIT DNS module

Terraform module which manages [STACKIT DNS](https://registry.terraform.io/providers/stackitcloud/stackit/latest/docs/resources/dns_zone) zones and record sets on [STACKIT](https://www.stackit.de/en/).

This repository is not from the official STACKIT organization.

## Usage

```hcl
module "dns" {
  source  = "terraform-stackit-modules/dns/stackit"
  version = ">= 1.0.0"

  project_id = "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"

  zones = {
    main = {
      name          = "my-zone"
      dns_name      = "example.com"
      type          = "primary"
      contact_email = "hostmaster@example.com"
      default_ttl   = 3600
    }
  }

  records = {
    www = {
      zone_key = "main"          # references the "main" key in `zones`
      name     = "www.example.com"
      type     = "A"
      records  = ["192.0.2.10"]
      ttl      = 300
    }
    root_mx = {
      zone_key = "main"
      name     = "example.com"
      type     = "MX"
      records  = ["10 mail.example.com"]
    }
  }
}
```

See [`examples/basic`](./examples/basic) for a self-contained example (requires only `project_id`).

## Notes

- Both `zones` and `records` are maps keyed by a **stable identifier**. A record references its
  zone through `zone_key` (a key in `zones`), so `for_each` never runs over a known-after-apply
  `zone_id`. A validation rejects a `zone_key` that does not exist in `zones`.
- Zone `type` is validated against `primary` / `secondary`.
- `stackit_dns_zone` / `stackit_dns_record_set` are region-agnostic — this module has no `region`
  variable.

## Terratest

The `test/` directory holds a Terratest integration test that applies the `examples/basic` root module against a real STACKIT project (requires `STACKIT_SERVICE_ACCOUNT_KEY` and `STACKIT_PROJECT_ID`).

```bash
cd test
go mod init github.com/terraform-stackit-modules/terraform-stackit-dns
go get github.com/gruntwork-io/terratest@v1.0.1
go mod tidy
go test -v -timeout 45m ./...
```
